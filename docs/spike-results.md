# Результаты spike рисков (шаг 1)

Дата: 2026-11-17. Все AX-замеры выполнены внутри `TermGrid.app` (`--probe`), право Accessibility выдано приложению, не терминалу. Evidence: `.omc/evidence/probe/` и `.omc/evidence/step-1-probe.txt`.

Решение пользователя: окна Terminal.app и iTerm2 в замерах не участвуют. Поэтому разделы b и c по терминалам не сняты, оценки по ним взяты из единственного прогона на рабочем окне iTerm2 и помечены как справка.

## Итог

| Раздел | Статус |
|---|---|
| a) TCC и подпись | снято частично: ad-hoc проверен, self-signed не проверен (сертификата нет) |
| b) латентность | снято на собственных окнах, по терминалам не снято |
| c) шаг символов | не снято (терминалы исключены) |
| d) non-activating панель | снято частично: фокус, события, курсор; Spaces и уровень не сняты |
| e) окно с фиксированным размером | снято |

## a) TCC и подпись

| Способ подписи | Результат |
|---|---|
| ad-hoc (`-s -`) | право Accessibility привязано к cdhash. После каждой пересборки право для новой сборки не действует, хотя запись в настройках остаётся. Лечится `tccutil reset Accessibility local.termgrid.TermGrid` и повторной выдачей. Наблюдалось несколько раз за сессию |
| self-signed "TermGrid Dev" | не проверялся: `security find-identity -v -p codesigning` выдаёт 0 identity |

Запрос права из приложения работает: `AXIsProcessTrustedWithOptions` с `kAXTrustedCheckOptionPrompt` показывает системный диалог, право выдаётся при работающем процессе, `AXIsProcessTrusted()` становится true без перезапуска (evidence: `out-6-safety.ndjson`, `out-7-bench-own.ndjson`). Диалог только открывает Системные настройки, включить переключатель в нём нельзя.

Принятое решение: для разработки ad-hoc плюс `scripts/probe.sh --reset`; в README описать оба пути и рекомендовать self-signed. Риск R-1 остаётся открытым до проверки self-signed.

## b) Латентность записи и частота

Собственные окна (`tgprobe test-windows --count 5`, 570×494 по AX (462 — размер содержимого, остальное заголовок), окна `TGTEST 1…5`, отдельный процесс; evidence `out-7-bench-own.ndjson`). Это нижняя граница: пустое окно AppKit не перерисовывается.

| Что | p50, ms | p95, ms | max, ms |
|---|---|---|---|
| запись size | 0.12 | 0.21 | 5.6 |
| пара size+position | 0.34 | 0.93 | 5.5 |

| k | p50 круга, ms | p95 круга, ms | max круга, ms | Гц на окно |
|---|---|---|---|---|
| 1 | 0.33 | 0.47 | 5.4 | 2117 |
| 2 | 0.75 | 5.8 | 9.5 | 172 |
| 4 | 1.5 | 8.0 | 8.6 | 126 |
| 5 | 1.7 | 7.8 | 10.3 | 129 |

Справка, iTerm2 (один прогон на рабочих окнах пользователя, 60 замеров, evidence `out-4-spike-iterm2.ndjson`; итогом не считается): пара size+position p50 9.0, p95 13.1, max 18.4 ms. Круг k=1: p95 12.2; k=2: 41.0; k=4: 79.1; k=5: 91.3 ms (12.6 Гц на окно при k=4).

Выводы:
- Стоимость самого AX-вызова мала (около 0.1–1 ms). Время определяет приложение окна: при k=4 у iTerm2 порог 66 ms из плана не достигнут (79.1 ms).
- Пользователь принял ~12 Гц на окно при больших сетках. Это решение основано на справочных числах iTerm2 и не подтверждено на чистых замерах.
- Terminal.app и браузер не измерялись.
- `maxApplyHz` по формуле `min(30, floor(1000 / P))` с P по iTerm2 (13.1 ms) равен 30. Принято: `maxApplyHz = 30` как верхняя граница, значение настраиваемое; адаптивное снижение по числу окон проверяется в шаге 7.
- Таймаут T: остаётся 0.25 s по умолчанию.

## c) Шаг символов

Не снято по решению пользователя (терминалы исключены). Справка: в одном прогоне по окну iTerm2 запросы ширины 800…810 и высоты 500…520 были приняты точно (фактический размер равен запрошенному, позиция не менялась), то есть деficит 0 px по обеим осям на профиле с плавным ресайзом; профиль и шрифт не записаны.

Следствие для `FitPolicy` (шаги 3 и 6): значения `charW` и `charH` для допуска ±1 символ берутся из настроек по умолчанию, пока их не измерят на терминалах. Принятое решение: допуск шага символов остаётся по плану, критерии с ним проверяются при появлении терминалов.

## d) Non-activating панель

Условия: `TermGrid --spike-panel 300 300 8 400` (панель 8×400 в координатах AppKit 300,300; высота основного экрана 1440, значит в AX x=300…308, y=740…1140, уровень `.normal`), `tgprobe drag` 304,800 → 304,1000, 20 шагов, запрошено 600 ms, фактически 649.5 ms; evidence `out-8-spike-d.ndjson`, журнал событий панели `step-1-spike-d-log.txt`.

| Проверка | Результат |
|---|---|
| Фокус не уходит после drag по панели | фокус остался у `com.apple.finder` до, после drag и после `cursor-at` |
| События доходят панели (лог `local.termgrid:ui`) | mouseDown 1, mouseDragged 20, mouseUp 1, mouseEntered 3, mouseExited 2. `deltaX/deltaY` в синтетических событиях равны 0, положение нужно брать из `locationInWindow` |
| Курсор resize из неактивного приложения | не сработал: на 200 ms и 1 s `hotSpot` 5,5, `image` 28×40, `matchesResizeLeftRight=false` (resize: hotSpot 15,12, image 30×24) |
| Панель не видна на соседнем Space | не снято: переключение Space меняет рабочий стол пользователя |
| Уровень `.normal`: перехват клика окном-соседом | не снято |

Ограничение защиты `TGTEST`: `drag` и `cursor-at` посылают глобальные события мыши и защитой не покрыты; в spike они применялись только над собственной панелью. Правило для дальнейших шагов: `drag` запускать только по координатам собственной панели.

Принятое решение: курсор ↔ из неактивного приложения не гарантирован, значит запасной вариант обязателен: подсветка разделителя при наведении (`mouseEntered`/`mouseExited` приходят). Уровень панели и поведение по Spaces решаются в шаге 7 на реальных панелях. До этого в риски добавлена строка: «панель-разделитель может перехватывать клики поверх неуправляемых окон».

## e) Окно с фиксированным размером

`tgprobe fixed-window --title TGTEST-fixed`, затем `list` через `--probe` (evidence `out-8-spike-d.ndjson`): subrole `AXStandardWindow`, `positionSettable=true`, `sizeSettable=false`.
Принятое решение: окно без изменяемого размера определяется по `sizeSettable=false`, а не по subrole.
